LinkedHashMap (class):
----------------------
LinkedHashMap is a subclass of HashMap that maintains insertion 
	order (or access order, if configured).
It combines:
HashMap’s fast performance (O(1) lookups)
LinkedList’s ordering feature
It was introduced in Java 1.4 and is part of java.util package.

3. Internal Structure:
----------------------
It internally maintains a doubly linked list running through all entries of the HashMap.
An array of buckets (like HashMap)
Plus, each node also keeps links to its previous and next node.

class Node<K,V>
{
final int hash;
final K kay;
V value;
Node<K,V> next;
Node<K,V> before;
Node<K,V> after;
}


| Feature          | Description                                 |
| ---------------- | ------------------------------------------- |
| Ordering         | Maintains   insertion order   by default    |
| Access Order     | Can maintain   access order   if configured |
| Null             | One null key, multiple null values allowed  |
| Duplicates       | Keys: not allowed, Values: allowed          |
| Thread-safe      | Not synchronized                            |
| Performance      | Almost same as HashMap                      |
| Load Factor      | Default 0.75                                |
| Initial Capacity | Default 16                                  |

5. Constructors:

LinkedHashMap<Integer, String> map1 = new LinkedHashMap<>();

// maintain access order (true)
LinkedHashMap<Integer, String> map2 = new LinkedHashMap<>(16, 0.75f, true);

Access Order:
-------------
import java.util.*;

public class AccessOrderDemo 
{
    public static void main(String[] args) 
	{
        LinkedHashMap<Integer, String> map =
            new LinkedHashMap<>(16, 0.75f, true);

        map.put(1, "A");
        map.put(2, "B");
        map.put(3, "C");

        map.get(1); // accessing key 1 moves it to end

        System.out.println(map);
        // Output: {2=B, 3=C, 1=A}
    }
}


Use LinkedHashMap:

Need fast lookup + predictable order

Want to preserve insertion order

Implement caches or LRU algorithms (least recently used).
