1. Data:
--------
Definition:
	-> Raw, unprocessed facts, figures, or symbols without context or meaning.
	-> It could be numbers, characters, images, sounds, or raw observations.
	here:
	42, 65, 90 ->  Just numbers, we don’t know what they represent?.
	"John, 25, 72kg" → Just raw values about someone.
	
2. Information:
---------------
Definition: 
	-> Processed, organized, or structured data that has meaning and is useful for decision-making.
	-> Data + Context = Information.
here, 
-> "42, 65, 90" (data) → “These are students’ test scores.” (information).
-> "John, 25, 72kg" (data) → “John is 25 years old and weighs 72kg.” (information).

Database :
----------
-> A Database (DB) is an organized collection of data that is stored and 
	managed so it can be easily accessed, retrieved, updated, and managed.
-> It is not just random files — it has structure and often follows certain rules.
	
	Advantages:
	-----------
> Organized data:
	Data is arranged in tables, rows, and columns (in relational databases).
> Efficient access:
	We can quickly search, insert, update, and delete data.
> Managed by DBMS:
	A Database Management System (DBMS) is software that helps in managing 
		the database (like MySQL, Oracle, PostgreSQL, MongoDB, etc.).

DBMS (Database Management System):
----------------------------------
-> A DBMS is software that helps you create, manage, and use databases.
-> A Database Management System (DBMS) is a software application
	that allows users to create, manage, and interact with databases 
	by providing a structured, secure, and efficient way to store, 
	retrieve, and update data. It acts as an interface between the database 
	and the users or other applications, ensuring data accuracy, accessibility, 
	and integrity. 
	
	Functions of DBMS:
	-------------------
	1. Data Manipulation:
		-> Inserting, updating, and deleting data within the database.
	2. Data Retrieval:
		-> Querying the database to find and display specific data based on 
			user-defined criteria. 
	3. Data Administration:
		-> Managing users, enforcing security, monitoring performance, 
			controlling data concurrency, and recovering data from failures. 
	Advantages:
	-----------
	Organization:
		-> Structures data into an organized and efficient system, 
			like a well-managed file cabinet, making it easy to 
				find information quickly.		
		-> Security:
			Provides a "safe" with locks and keys to protect data from unauthorized access,
				ensuring only legitimate users can view and manipulate it. 
		-> Data Integrity:
			Validates and enforces rules for data entry and storage, 
				preventing errors like duplicate entries or incorrect data types.
		-> Easy Access:
			Allows users to ask specific questions of the data and receive 
				organized results, simplifying the process of finding needed information. 
		-> Concurrency Control:
			Manages simultaneous access by multiple users, ensuring data consistency. 
		-> Backup and Recovery:
			Helps in recovering corrupted data after unexpected system failures.

Components Inside DBMS:
-----------------------
1. Query Parser:
	DBMS checks query syntax.
2. Optimizer:
	Decides best way to find students in class 10 (index search vs full scan).
3. Execution:
	Fetches matching rows from storage.
4. DDL Compiler:
	Handles Data Definition Language commands (like CREATE TABLE, ALTER TABLE).
	DML Compiler
5. Query Optimizer:
	Decides the most efficient way to execute 
		queries (e.g., use an index instead of scanning the whole table).
6. Transaction Manager:
	Ensures ACID properties (Atomicity, Consistency, Isolation, Durability) 
	to safe and reliable transactions.
7. Buffer Manager:
	Manages data in memory (RAM) to reduce slow disk reads.
8. Recovery Manager:
	Restores data after crashes or failures using logs & backups.
9. Authorization Manager
	Ensures security (only authorized users can access data).
	
DBMS Architectures:
------------------
A DBMS architecture defines how users, applications, and the database are connected.
There are mainly 4 types: 1-Tier, 2-Tier, 3-Tier, and N-Tier.
	
1-Tier Architecture:
--------------------
Everything happens on a single machine.
The user, application, and DBMS all run on the same system.

2-Tier Architecture:
--------------------
Here, we separate the application (client) and the database (server).
The client (UI app) talks directly to the DBMS server.
A Java Spring application that connects to MySQL using JDBC.

3-Tier Architecture:
--------------------
Adds a middle layer (application server) between the client and DB.
Client → Application Server → DB Server.
Application server handles business logic, security, validation.

Client: Browser (UI)
Middle: Spring Boot/Node.js/PHP server
DB Server: MySQL/Oracle

N-Tier Architecture (Multi-Tier):
---------------------------------
Common in enterprise-level applications.
micro-service projects


ACID Properties in DBMS:
------------------------
transaction -> a single logical unit of work
DBMS uses ACID to make sure transactions are safe and reliable.

1. Atomicity ("All or Nothing"):
--------------------------------
-> A transaction should be fully completed or not done at all.
-> If any step fails, the whole transaction rolls back.
example:
	-> If money is deducted from A but not added to B (due to error),
	-> the DBMS will rollback to the original state (A still has money).
2. Consistency ("Valid State"):
-------------------------------
-> A transaction should take the database from one valid state to another valid state.
-> No rules/constraints should be broken.
example:
	If a column "Age" must be positive, 
		inserting Age = -5 is invalid → DBMS won’t allow it.
3. Isolation ("No Interference"):
--------------------------------
-> When multiple transactions run at the same time, 
	they should not affect each other’s correctness.
-> DBMS ensures concurrent transactions appear as if they
		were executed one after another.
example:
	-> Two people booking the last movie ticket at the same time.
	-> Without isolation → both might get the ticket (wrong).
	-> With isolation → only one succeeds, the other gets “Sold Out.”
4. Durability ("Permanent"):
----------------------------
-> Once a transaction is committed, the changes are permanent, even if the system crashes.
-> DBMS uses logs and backups to restore data.

| Property        | Meaning                        | Example (Bank Transfer)                        |
| --------------- | ----------------------------   | ---------------------------------------------- |
|  Atomicity      | All steps succeed or none      | Deduct from A, add to B — both must happen     |
|  Consistency    | DB rules not violated          | Balance never becomes negative if rule says so |
|  Isolation      |   Transactions don’t interfere | Two people can’t take the same seat            |
|  Durability     | Once saved, always saved       | Power cut won’t undo a completed transfer      |

Constraint:
-----------
A constraint in a database is a rule applied to a table or column that controls 
what data is allowed to be stored.

| Constraint     | Purpose                    |
| -------------- | -------------------------- |
| PRIMARY KEY    | Unique row identifier      |
| UNIQUE         | Prevent duplicate values   |
| NOT NULL       | Mandatory value            |
| DEFAULT        | Auto value if not provided |
| AUTO_INCREMENT | Auto-generate numbers      |

PRIMARY KEY:
------------
Uniquely identifies each row in a table

Cannot be NULL

Only one primary key per table

CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    dept VARCHAR(30)
);

id must be unique and not null

UNIQUE:
-------
Ensures all values in a column are different

Allows NULL values (only one NULL in MySQL)

CREATE TABLE employee (
    emp_id INT,
    email VARCHAR(100) UNIQUE
);

No two employees can have the same email

NOT NULL:
---------
Column must have a value

NULL values are not allowed

CREATE TABLE user (
    user_id INT,
    username VARCHAR(50) NOT NULL
);

Cannot insert a row without username

DEFAULT:
--------
Sets a default value if no value is provided during insert

CREATE TABLE orders (
    order_id INT,
    status VARCHAR(20) DEFAULT 'PENDING'
);


INSERT INTO orders (order_id) VALUES (101);

status will automatically be PENDING

Clauses:
--------
In MySQL, clauses are keywords used in a SQL statement to define what data you 
want and how you want it.
Each clause performs a specific role in querying, filtering, sorting, or grouping data.
SQL query as a sentence and clauses as its parts.

SELECT Query Structure:

SELECT column_name
FROM table_name
WHERE condition
GROUP BY column_name
HAVING condition
ORDER BY column_name
LIMIT number;

SELECT Clause:

Used to choose columns to display.
SELECT name, salary FROM employee;

FROM Clause:

Specifies which table to read data from.
SELECT * FROM employee;

WHERE Clause

Filters rows based on conditions.
SELECT * FROM employee WHERE department = 'IT';

GROUP BY Clause

Groups rows with same values (used with aggregate functions).
SELECT department, COUNT(*) 
FROM employee
GROUP BY department;

HAVING Clause:

Filters groups (used after GROUP BY).
SELECT department, COUNT(*) 
FROM employee
GROUP BY department
HAVING COUNT(*) > 5;

ORDER BY Clause:

Sorts the result set by ASC or DESC
SELECT * FROM employee ORDER BY salary DESC;

LIMIT Clause:

Restricts the number of rows returned.
SELECT * FROM employee LIMIT 5;

DISTINCT Clause:

Removes duplicate values.
SELECT DISTINCT department FROM employee;

JOIN

A JOIN is used in SQL to combine rows from two or more 
tables based on a related column between them.

1. INNER JOIN:
Returns only matching records from both tables.


SELECT s.name, d.dept_name
FROM student s
INNER JOIN department d
ON s.dept_id = d.dept_id;

2. LEFT JOIN:
----------
all records from the LEFT table
matched records from the RIGHT table

If no match exists → NULL


SELECT students.name, marks.mark
FROM students
LEFT JOIN marks
ON students.id = marks.id;

3. RIGHT JOIN:
--------------
all records from RIGHT table
matched records from LEFT table

SELECT students.name, marks.mark
FROM students
RIGHT JOIN marks
ON students.id = marks.id;

4. FULL JOIN:
-------------
MySQL does not directly support FULL OUTER JOIN.
But we can simulate it using:

LEFT JOIN
UNION
RIGHT JOIN

example:

SELECT students.name, marks.mark
FROM students
LEFT JOIN marks
ON students.id = marks.id

UNION

SELECT students.name, marks.mark
FROM students
RIGHT JOIN marks
ON students.id = marks.id;

5. CROSS JOIN:
--------------
Returns Cartesian Product.
Each row from first table combines with every row from second table.

SELECT colors.color, sizes.size
FROM colors
CROSS JOIN sizes;

6. SELF JOIN:
-------------
A table joins with itself.
Used when rows in the same table are related.

Index in MySQL
--------------
An index is a special data structure that helps MySQL find rows 
faster instead of scanning the entire table.

Without index:

	MySQL checks every row → Full Table Scan

With index:

	MySQL jumps directly to matching rows → Fast Search
Types of Indexes:
-----------------
1. Clustered Index

A clustered index determines the physical storage 
order of rows in the table.
The actual table data is stored in sorted order based 
on the clustered index column.
PRIMARY KEY automatically becomes the clustered index.
2. Non-Clustered Index:
-----------------------
A non-clustered index stores:

indexed column values
pointer/reference to actual rows

Table data is stored separately.
MySQL creates a separate B-Tree index structure internally.

create index:
-------------
CREATE INDEX index_name ON employee(column_name);

show index details:
-------------------
SHOW INDEX FROM table_name;

View
----
-> A View in MySQL is a virtual table created from a SQL query.
	It does not store data physically (normally).
-> Instead, it stores the SQL query and shows data from 
	one or more tables whenever you access it.
syntax:
-------
CREATE VIEW view_name AS
SELECT column1, column2
FROM table_name
WHERE condition;

Advantages of Views:
--------------------
1. Security
Hide sensitive columns.
2. Simplifies Complex Queries
Instead of writing joins repeatedly
3. Reusability
Write query once and use everywhere.
4. Data Abstraction
Users see only required data.

UNION:
------
UNION is used to combine the results of two or more SELECT 
queries into a single result set. It removes duplicate rows by default.

Important Rules of UNION
-------------------------
Number of columns must be the same in all SELECT queries

Data types must be compatible
	
Column names are taken from the first SELECT

Duplicates are removed automatically


syntax:

SELECT col1, col2 FROM table1
UNION
SELECT col1, col2 FROM table2;


| UNION                   | JOIN              |
| ----------------------- | ----------------- |
| Combines rows           | Combines columns  |
| Same structure required | Relation via keys |
| Vertical merge          | Horizontal merge  |

UNION ALL:
----------
If you want duplicates also, use UNION ALL

syntax:
SELECT col1, col2 FROM table1
UNION ALL
SELECT col1, col2 FROM table2;

Cursor:
-------
-> A Cursor in MySQL is used inside a Stored Procedure to process 
	rows one by one from a query result.
-> Normally SQL works on all rows together.
-> But sometimes we need row-by-row processing like loops in 
	programming languages.

Cursor Lifecycle:
-----------------
1. DECLARE cursor
2. OPEN cursor
3. FETCH rows one by one
4. CLOSE cursor

syntax:
-------
DECLARE cursor_name CURSOR FOR
SELECT column_name FROM table_name;

OPEN cursor_name;

FETCH cursor_name INTO variable;

CLOSE cursor_name;

NOT FOUND Handler:
------------------
When all rows are fetched, MySQL throws NOT FOUND condition.
use this after the cursor declaration

DECLARE CONTINUE HANDLER FOR NOT FOUND
---------------------------------------
delimiter //
create procedure print_employee_names()
begin 
	declare temp varchar(200) default '';
    declare username varchar(30);
    declare islast boolean default false;
    
    
    
    declare read_data cursor  for select emp_name from employee;
    
    DECLARE CONTINUE HANDLER FOR NOT FOUND
		set islast = true;
    
    open read_data;
    
    my_loop: loop 
    
    fetch read_data into username;
    set temp = concat(temp, ',', username);
    
    if islast then 
		leave my_loop;
    end if;
    
    end loop;
    close read_data;
    
    select temp;

end //
delimiter ;

drop procedure print_employee_names;

call print_employee_names();

TRANSACTION Control language:
------------------------------

| Command                 | Purpose                  |
| ----------------------- | ------------------------ |
|  START TRANSACTION      | Start transaction        |
|  COMMIT                 | Save changes permanently |
|  ROLLBACK               | Undo changes             |
|  SAVEPOINT              | Create checkpoint        |
|  ROLLBACK TO SAVEPOINT  | Undo to specific point   |

----------------
create database transaction_practice;
use transaction_practice;
drop database transaction_practice; 
create table user(
id int primary key auto_increment,
name varchar(20),
amount decimal(10,2)
); 

insert into user(name,amount) value('shahin',5000),('mahin',3000),('visal',4000);
drop table user;

start transaction;
savepoint point1;
update user set amount=amount-1000 where name = 'shahin';
savepoint point2;
update user set amount=amount+1000 where name = 'mahin';

select * from user;
rollback to point1;
rollback to point2;
rollback;
